Branch `feature/team-mailbox` off `origin/master`. FortDocs `feature/FD-676/inbox-addresses` is linked to this source with its switcher while both are developed.

## Steps

- [x] 0. NuGet update (`chore(deps)`); all 3378 tests green.
- [x] 1. **New package, pure move.** `Tharga.Team.Email` + `Tharga.Team.Email.Tests` (in the solution, on the pack list, in the root README): the transport moved with history into namespace `Tharga.Team.Email`, MailKit with it; `ISupportMailClient` → `IMailClient`, `SupportMailClient` → `MailClient` (renamed now so the new package is not renamed twice). The namespace-isolation guard scans both assemblies; the read-only scan points at the new folder and skips build output. Migration table in the package README.
- [x] 2. **Contracts** (`Tharga.Team`, namespace `Tharga.Team` like the support contracts): `TeamMailKey`, `TeamMailAddresses`, `MailKeyRole`, `MailEnvelope`, `MailRouteReason` (PrimaryKey, RetiringKey, RetiredKey, UnknownAddress, Rerouted), `MailThreadOwner`, `InboundMailItem` (host-defined `Outcome` string), `InboundMailPage`, `InboundMailFilter`, `PostmasterMailSummary` (deliberately thin), `PostmasterPage`, `MailContent` (raw bytes); `ITeamMailboxService` and `IPostmasterService` with `[RequireScope]` on every method (gated through the scope proxy rather than a decorator — the rules are plain scopes, unlike support's author rules); `IInboundMailContentStore` (overwrite on save); `ITeamMailNotifier` + `TeamMailUpdatedEventArgs` + `TeamMailChange`. **Three team scopes**, not two: `mailbox:read`, `mailbox:handle` (record an outcome — a case officer), `mailbox:manage` (issue/rotate — an administrator); system `mailbox:postmaster:read|manage`. `MailboxContractShapeTests` (Service.Tests) pins: every method scoped, team service team-first with team scopes, postmaster system scopes only, no overlap, opening unrouted mail audited, changes recorded as changes, wire-shaped. All green.
- [x] 3. **Address and key rules** (`Tharga.Team.Email`, namespace `Tharga.Team.Email.Mailbox` so the transport namespace's isolation guard still holds; Email now references `Tharga.Team`): `TeamMailboxOptions` (Domain, Suffix, KeyLength 12, RetirementPeriod 90 days) public; `MailKeyGenerator` (RandomNumberGenerator over a-z0-9, 8–64), `TeamMailAddress` (build, item build refusing `+ @` whitespace, parse: case-insensitive, `<>` tolerated, key must be a-z0-9), `StoredMailKey` (retired at the retirement moment, not after), `MailRoute.Decide` (first delivery address that is ours decides; primary → team, secondary before retirement → team marked RetiringKey with the date, retired → postmaster RetiredKey, unknown or none of ours → postmaster UnknownAddress) — internal. 32 tests.
- [x] 4. **Rotation**: port `ITeamMailKeyStore` + `TeamMailKeyRecord` in `Tharga.Team` (domain language; `RotateAsync` is one atomic operation; `IssueAsync` refuses a second primary so two instances end with one key; retired keys kept so mail to them reads as retired, not unknown). The step-3 `StoredMailKey` gave way to the port's record. `TeamMailboxService` (internal, behind `AddTeamService` → scope proxy, which audits per the attribute's mode): `GetAddressesAsync`, `GetItemAddressAsync`, `EnsureKeyAsync` (re-reads after a lost race), `RotateKeyAsync` (first rotation issues; retirement from options); keys checked unused before issue. Mail operations throw `NotSupportedException` until step 7. `AddThargaTeamMailbox` (refuses a missing domain or bad key length at registration), `TeamMailNotifier` singleton, team scopes at host-chosen levels (`ReadAccessLevel`/`HandleAccessLevel` User, `ManageAccessLevel` Administrator, null = grant-only), system postmaster scopes. Email now references `Tharga.Team.Service`. 20 tests; all 3466 green.
- [-] 5. **Thread tracker** — moved to the FD-769 follow-up (2026-10-15): nothing on this branch sends mail, so a tracker would record nothing and match nothing. Mail to an item address already reaches its item through routing (`ItemKey`).
- [x] 6. **Mongo adapters** (`Tharga.Team.MongoDB`): port `ITeamMailStore` in `Tharga.Team` (add = dedupe, team reads name the team, postmaster = no team, `RouteAsync` moves only what the postmaster still holds, deletes return ids so content can go too). **Keys: one document per team** (`TeamMailKeysEntity` with `Keys[]` and `Revision`) so a rotation is one conditional write — no transaction or replica set needed; unique `TeamKey` makes the first issue atomic, unique `Keys.Key` keeps a key (retired too) from ever reaching two teams. **Mail:** `InboundMailEntity` (+ `MailEnvelopeEntity`, never the contract as storage) with unique, non-expiring `MailId`; keyset paging on received time (`{ticks}:{mailId}`, newest first, capped at 500), a foreign cursor refused. Collection names in `ThargaTeamOptions` (`TeamMailKey`, `InboundMail`); TryAdd + TrackMongoCollection. 15 tests; the persisted-enum guard covers the new entities. Read position moves to step 7 (the poller owns it); the purge participant to step 8 (team removal must delete raw content too, through the content store).
- [x] 7. **Receiving**: `InboundMail` gains optional `Uid`, `Raw`, `FromName`, `To`, `Cc` (reader fills them; raw only when a fetch asks — an internal `MailClient.FetchAsync(position, includeRaw)`, so support's fetch and the public `IMailClient` are unchanged). `TeamMailboxOptions.Mail` = the catch-all mailbox's own IMAP settings. `InboundMailId` = SHA-256 of Message-Id + delivered-to (one mail to two teams is two deliveries), of the raw bytes when there is no Message-Id. `MailRoute.DecideAsync`. `TeamMailReceiver`: route → **content saved first** → unique add → notify only when new. `TeamMailboxPoller` (registered only with IMAP settings; refuses to start without an `IInboundMailContentStore`, naming it): every instance polls, no coordination; **a mail that fails holds the position just before it** (support's poller moves on; organisation mail may already count as received). Position kept through `ISupportMailPositionStore` under `team-mailbox|{folder}` — reused rather than a second port; its name is now wider than support (naming debt, noted for the follow-up). Service mail operations implemented (handled-by = the caller's subject via `TeamAuthorizer`; content via the host store; another team's id reaches nothing). 25 tests.
- [x] 8. **Postmaster**: `PostmasterService` behind `AddSystemService` (the proxy audits every open per the attribute): list = summaries only (sender, subject, time, reason), count, open and content only for mail with no team, `RouteAsync(mailId, toTeamKey)` — renamed from `teamKey` because the toolkit's own guard refuses `teamKey` on a system service, and rightly: the team is the destination, never the authority; refuses an empty or unknown team when a team service is registered; moves a mail once; announces `Rerouted`. `PostmasterRetentionSweep` (with the poller; every 6 h) deletes unrouted mail older than `PostmasterRetention` (default 90 days) with its content, one audited `DataChange` per mail (`mailbox.mail.id`), as a background actor. `TeamMailboxPurgeParticipant`: a removed team's mail, content and keys go (its addresses become unknown, so later mail reaches the postmaster, never a team that draws the same key). The read-only source scan now looks at MailKit files for folder opens (it had started matching `PostmasterService.OpenAsync`); the mutation scan still covers everything. 14 tests; all 3495 green.
- [x] 9. **Blazor** (`Tharga.Team.Blazor`, contracts only — no reference to `Tharga.Team.Email`, so no MailKit): `PostmasterView` (thin list with reason and count, a note that opening is recorded, open shows the envelope, route to a team picked from `ITeamOversightService` when the reader may list teams, otherwise typed; "already gone" when someone else routed it first; follows the notifier; load more by cursor) and `TeamMailAddressView` (address with copy, the retiring address as a warning with its date, create when none, change only after a confirm that says senders must be told; refusal shown, never the address). `PostmasterViewText` / `TeamMailAddressViewText`; both views written against the catalogue from the start and listed in `TextCoverageTests`; `TimeTemplate` lets a host render moments. The mailbox services join the optional-package list in `ComponentDependencyResolutionTests`, as support's do. 9 render tests (bUnit); all green.
- [x] 10. **Invitations onto the shared transport.** `SmtpTeamEmailSender` (System.Net.Mail, `Tharga.Team.Service`) removed with its tests; `InvitationMailSender` in `Tharga.Team.Email` sends through `MailClient` — one SMTP stack — with the same body, the same policy decision and the same refusal to log the recipient, and **throws when the send fails** (the transport only reports it, and the invite dialog learns of failure only from an exception). `AddThargaEmailInvitations(configure?)` registers it with `TryAdd`, so a host's own sender wins in either order. `EmailOptions` stays in Service; `ThargaBlazorOptions.Email` still configures it, and Blazor now registers `InvitationSenderCheck` instead of a sender: a startup warning naming the package and the call when settings exist and no sender does. **TLS:** `MailClient` now maps `UseSsl` on 587/25 to required STARTTLS (what `EnableSsl` meant; it used to try TLS-on-connect there and fail) and elsewhere to TLS-on-connect; without it, TLS when offered — support's working settings are unchanged. Transport log and error text no longer say "support". No `System.Net.Mail` left in the solution. 18 tests; all green. FortDocs (linked): 33 new view keys lack Swedish and the "team" wording trips its organisation rule — FortDocs F5's job when it takes the views.
