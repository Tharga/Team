All green.
- [x] 3. **Address and key rules** (`Tharga.Team.Email`, namespace `Tharga.Team.Email.Mailbox` so the transport namespace's isolation guard still holds; Email now references `Tharga.Team`): `TeamMailboxOptions` (Domain, Suffix, KeyLength 12, RetirementPeriod 90 days) public; `MailKeyGenerator` (RandomNumberGenerator over a-z0-9, 8–64), `TeamMailAddress` (build, item build refusing `+ @` whitespace, parse: case-insensitive, `<>` tolerated, key must be a-z0-9), `StoredMailKey` (retired at the retirement moment, not after), `MailRoute.Decide` (first delivery address that is ours decides; primary → team, secondary before retirement → team marked RetiringKey with the date, retired → postmaster RetiredKey, unknown or none of ours → postmaster UnknownAddress) — internal. 32 tests.
- [x] 4. **Rotation**: port `ITeamMailKeyStore` + `TeamMailKeyRecord` in `Tharga.Team` (domain language; `RotateAsync` is one atomic operation; `IssueAsync` refuses a second primary so two instances end with one key; retired keys kept so mail to them reads as retired, not unknown). The step-3 `StoredMailKey` gave way to the port's record. `TeamMailboxService` (internal, behind `AddTeamService` → scope proxy, which audits per the attribute's mode): `GetAddressesAsync`, `GetItemAddressAsync`, `EnsureKeyAsync` (re-reads after a lost race), `RotateKeyAsync` (first rotation issues; retirement from options); keys checked unused before issue. Mail operations throw `NotSupportedException` until step 7. `AddThargaTeamMailbox` (refuses a missing domain or bad key length at registration), `TeamMailNotifier` singleton, team scopes at host-chosen levels (`ReadAccessLevel`/`HandleAccessLevel` User, `ManageAccessLevel` Administrator, null = grant-only), system postmaster scopes. Email now references `Tharga.Team.Service`. 20 tests; all 3466 green.
- [-] 5. **Thread tracker** — moved to the FD-769 follow-up (2026-10-15): nothing on this branch sends mail, so a tracker would record nothing and match nothing. Mail to an item address already reaches its item through routing (`ItemKey`).
- [x] 6. **Mongo adapters** (`Tharga.Team.MongoDB`): port `ITeamMailStore` in `Tharga.Team` (add = dedupe, team reads name the team, postmaster = no team, `RouteAsync` moves only what the postmaster still holds, deletes return ids so content can go too). **Keys: one document per team** (`TeamMailKeysEntity` with `Keys[]` and `Revision`) so a rotation is one conditional write — no transaction or replica set needed; unique `TeamKey` makes the first issue atomic, unique `Keys.Key` keeps a key (retired too) from ever reaching two teams. **Mail:** `InboundMailEntity` (+ `MailEnvelopeEntity`, never the contract as storage) with unique, non-expiring `MailId`; keyset paging on received time (`{ticks}:{mailId}`, newest first, capped at 500), a foreign cursor refused. Collection names in `ThargaTeamOptions` (`TeamMailKey`, `InboundMail`); TryAdd + TrackMongoCollection. 15 tests; the persisted-enum guard covers the new entities. Read position moves to step 7 (the poller owns it); the purge participant to step 8 (team removal must delete raw content too, through the content store).
